# 07. INTELIGÊNCIA ARTIFICIAL

## Sigma — Configuração Inicial da Inteligência Artificial Local com Ollama

### 1. Introdução

O Sigma é um projeto de assistente financeiro pessoal desenvolvido com Python, cujo objetivo é auxiliar os usuários na organização e no acompanhamento de suas finanças por meio de uma interface conversacional.

A proposta é permitir que o usuário envie mensagens em linguagem natural, como _"Gastei R$ 50 no Uber"_ ou _"Recebi R$ 500 de salário"_, para que o sistema consiga interpretar essas informações e, futuramente, utilizá-las no registro e na consulta de movimentações financeiras.

Nesta etapa do desenvolvimento, o foco foi configurar o ambiente de execução, preparar a estrutura inicial do projeto e integrar um modelo de inteligência artificial local utilizando o Ollama.

### 2. Escolha da tecnologia

Inicialmente, foi considerada a utilização de uma API de inteligência artificial externa. Entretanto, devido aos custos que poderiam estar associados ao uso contínuo desse serviço, optou-se por utilizar o Ollama para executar um modelo de linguagem localmente.

O Ollama permite baixar e executar modelos de linguagem no próprio computador, possibilitando que aplicações Python interajam com eles sem depender necessariamente de uma API comercial externa.

Para o Sigma, essa escolha permite explorar o processamento de linguagem natural e desenvolver a lógica de interpretação das mensagens financeiras sem gerar custos por requisição a uma API paga.

É importante destacar que a execução local ainda depende dos recursos de hardware disponíveis, como memória RAM, processador e, quando aplicável, placa de vídeo.

### 3. Tecnologias utilizadas

Nesta fase, foram utilizadas ou configuradas as seguintes tecnologias:

### 4. Configuração do ambiente

#### 4.1. Preparação do Python

O projeto foi configurado no PyCharm utilizando um ambiente Python gerenciado pelo Conda. Essa configuração permite manter as dependências do Sigma separadas de outros projetos e facilita a reprodução do ambiente de desenvolvimento.

#### 4.2. Instalação do Ollama

O aplicativo Ollama foi instalado no Windows e sua disponibilidade foi verificada pelo terminal utilizando o comando:

```
ollama --version
```

A execução desse comando permitiu confirmar que o Ollama estava acessível pelo terminal.

#### 4.3. Download do modelo

Foi selecionado inicialmente o modelo `llama3.2:1b`, utilizando o comando:

```
ollama run llama3.2:1b
```

Esse comando permite baixar o modelo caso ele ainda não esteja disponível localmente e iniciar uma sessão de conversação no terminal.

O modelo foi executado com sucesso e respondeu às mensagens enviadas durante os testes iniciais.

#### 4.4. Instalação da biblioteca Python

Para permitir que o código Python se comunique com o Ollama, foi instalada a biblioteca correspondente no ambiente utilizado pelo PyCharm:

```
python -m pip install ollama
```

A utilização de `python -m pip` ajuda a direcionar a instalação para o interpretador Python associado ao comando executado. É importante garantir que esse interpretador seja o mesmo configurado no projeto.

Após a instalação, foi verificado que a biblioteca podia ser importada:

```
import ollama
```

Essa etapa estabeleceu a base para realizar chamadas ao modelo diretamente pelo código Python.

### 6. Primeira comunicação entre Python e Ollama

Após configurar o ambiente e instalar a biblioteca, foi preparado um teste de comunicação entre o Python e o modelo.

O exemplo abaixo demonstra a estrutura utilizada para enviar uma mensagem ao modelo e exibir a resposta:

```
import ollama

response = ollama.chat(
    model="llama3.2:1b",
    messages=[
        {
            "role": "user",
            "content": "Gastei R$ 50 no Uber hoje."
        }
    ]
)

print(response.message.content)
```

Nesse código:

1. A biblioteca `ollama` é importada.
2. A função `ollama.chat()` envia uma mensagem ao modelo selecionado.
3. O parâmetro `model` identifica o modelo que será utilizado.
4. A lista `messages` contém as mensagens da conversa.
5. O campo `role` identifica quem enviou a mensagem.
6. O campo `content` contém o texto enviado.
7. A resposta gerada pelo modelo é acessada por `response.message.content` e exibida no terminal.

Esse teste demonstra a comunicação entre a aplicação Python e o modelo local. Entretanto, ele ainda não registra movimentações financeiras nem consulta um banco de dados.

### 7. Criação de instruções para a IA

Durante os testes iniciais, foi observado que o modelo conseguia responder às mensagens, mas nem sempre apresentava o comportamento esperado para um assistente financeiro.

Isso ocorre porque um modelo de linguagem genérico não conhece automaticamente todas as regras específicas da aplicação. Para direcionar suas respostas, foi planejada a utilização de uma mensagem de sistema, conhecida como _system prompt_.

Foi proposta a criação do arquivo `src/ai/instructions.py`, responsável por armazenar as instruções principais do Sigma.

O conteúdo inicial proposto foi:

```
SYSTEM_PROMPT = """
Você é o Sigma, um assistente financeiro pessoal
que ajuda usuários a organizar suas finanças.

SUAS RESPONSABILIDADES:
1. Interpretar mensagens sobre receitas e despesas.
2. Identificar solicitações de consultas financeiras.
3. Responder a dúvidas gerais sobre organização financeira.
4. Pedir esclarecimentos quando não houver informações suficientes.

REGRAS PARA TRANSAÇÕES:
- Identifique se a movimentação é uma receita ou despesa.
- Extraia o valor, a descrição, a categoria e a data,
  quando essas informações estiverem disponíveis.
- Não invente valores, datas ou informações ausentes.
- Se não for possível identificar o valor, peça esclarecimentos.
- Não afirme que uma transação foi salva sem confirmação
  do sistema Python.
- Não invente saldos, totais ou históricos financeiros.

COMPORTAMENTO:
- Responda em português brasileiro.
- Seja claro, educado e objetivo.
- Não registre transações para mensagens que sejam apenas
  saudações ou conversas comuns.
- Quando o usuário pedir uma operação que dependa de dados
  ainda não disponíveis, explique essa limitação.
"""
```

O objetivo dessas instruções é estabelecer o comportamento esperado da IA, orientar a identificação de informações financeiras e reduzir respostas inadequadas.

**Observação:** esse conteúdo foi proposto como instrução inicial. Sua presença e seu funcionamento devem ser confirmados no projeto antes de considerar essa parte concluída.

### 8. Integração das instruções ao modelo

Após definir o texto de instruções, a chamada ao Ollama pode ser adaptada para incluir a mensagem de sistema.

O exemplo a seguir demonstra como essa integração pode ser realizada:

```
import ollama
from src.ai.instructions import SYSTEM_PROMPT

response = ollama.chat(
    model="llama3.2:1b",
    messages=[
        {
            "role": "system",
            "content": SYSTEM_PROMPT
        },
        {
            "role": "user",
            "content": "Gastei R$ 50 no Uber hoje."
        }
    ]
)

print(response.message.content)
```

Nesse exemplo, a mensagem de sistema apresenta as regras de comportamento, enquanto a mensagem do usuário contém a informação que deve ser interpretada.

A inclusão do _system prompt_ permite direcionar o modelo para a função de assistente financeiro. Entretanto, as instruções não garantem que todas as respostas estarão corretas. Por isso, as informações extraídas deverão ser verificadas pelo código Python antes de qualquer operação financeira.

### 9. Limitações identificadas

Os testes iniciais permitiram identificar algumas limitações importantes para o desenvolvimento do Sigma.

#### 9.1. Respostas dependentes das instruções

Sem orientações específicas, o modelo pode responder de forma diferente do comportamento desejado para um assistente financeiro. A criação de um _system prompt_ é uma primeira medida para direcionar essas respostas.

#### 9.2. Ausência de persistência de dados

Até esta etapa, a comunicação com o modelo não representa um sistema completo de gerenciamento financeiro. Ainda é necessário desenvolver uma forma de armazenar receitas e despesas, por exemplo, utilizando um banco de dados.

#### 9.3. Ausência de cálculos financeiros implementados

O modelo pode interpretar uma mensagem, mas os cálculos de saldo, totais de receitas, despesas e demais indicadores deverão ser realizados pelo Python, utilizando regras determinísticas.

Isso reduz a dependência de cálculos produzidos diretamente pelo modelo de linguagem.

#### 9.4. Ausência de saída estruturada validada

Uma resposta em texto livre pode dificultar a identificação automática dos campos necessários para registrar uma movimentação. Uma evolução planejada é solicitar uma saída estruturada, como JSON, e validar seu conteúdo antes de utilizá-lo.

Mesmo quando o modelo retorna JSON, o programa deverá verificar se o formato é válido, se o tipo de movimentação é permitido e se o valor informado é adequado.

#### 9.5. Limitações de hardware

Como o modelo é executado localmente, seu desempenho depende dos recursos do computador. Modelos menores podem reduzir o consumo de recursos, mas também podem apresentar limitações na qualidade das respostas e na interpretação de mensagens mais complexas.

### 10. Arquitetura planejada

A arquitetura do Sigma será organizada para separar a interpretação da linguagem natural das operações financeiras.

O fluxo planejado é:

1. **Entrada do usuário:** o usuário envia uma mensagem pelo chat.
2. **Interpretação pela IA:** o modelo local identifica a intenção e as informações relevantes.
3. **Validação pelo Python:** o programa verifica os dados extraídos e solicita esclarecimentos quando necessário.
4. **Execução da operação:** o código Python realiza a operação correspondente, como registrar ou consultar uma movimentação.
5. **Persistência:** os dados são armazenados ou consultados no banco de dados.
6. **Resposta ao usuário:** o sistema informa o resultado com base na operação efetivamente realizada.

Essa separação é importante porque o modelo de linguagem deve auxiliar na compreensão das mensagens, enquanto as regras de negócio e os cálculos financeiros permanecem sob controle do programa.

### 12. Conclusão

Nesta fase, foi preparada a base técnica para utilizar inteligência artificial local no Sigma. O ambiente Python foi configurado, o Ollama foi instalado, o modelo Llama 3.2 1B foi executado e a biblioteca Python foi utilizada para estabelecer a comunicação com o modelo.

A decisão de utilizar o Ollama estabelece uma base para continuar o desenvolvimento localmente, mantendo a interpretação das mensagens separada das regras financeiras responsáveis pela confiabilidade das operações.

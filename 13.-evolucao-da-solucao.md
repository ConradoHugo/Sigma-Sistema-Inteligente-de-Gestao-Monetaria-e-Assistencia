#### 4. Evolução da inteligência artificial

| **Fase**                       | **Descrição**                                                                                                                       |
| ------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------- |
| Protótipo em Python            | Configuração do Ollama, modelo `llama3.2:1b` e instruções (_system prompt_) para um assistente financeiro, descritos no capítulo 07 |
| Consultas determinísticas      | O assistente começou respondendo consultas financeiras de forma determinística                                                      |
| Ollama no backend Java         | As instruções foram incorporadas ao `OllamaAiProvider`, e o serviço passou a usar a API HTTP do Ollama                              |
| Histórico e contexto           | Até 12 mensagens recentes por conversa do usuário autenticado, sem compartilhar conversas entre contas                              |
| Classificação por esquema JSON | Rotas permitidas definidas por esquema, impedindo texto livre na classificação                                                      |
| Conversa direta                | Saudações e perguntas gerais seguem direto para o modelo; consulta de saldo tem encaminhamento explícito                            |
| Teste com modelo real          | `OllamaLiveTest` valida saudação, orientação e consulta de saldo                                                                    |

O princípio mantido em todas as fases: o modelo de linguagem auxilia na conversa, e os cálculos financeiros permanecem sob controle dos serviços Java.

#### 5. Evolução da interface e do fluxo

O protótipo passou de telas isoladas a um fluxo completo, que conecta cadastro, autenticação, lançamentos e resumos persistidos. Há evidências de navegação responsiva (1440, 768 e 390 pixels) e de funcionamento desktop registradas nos guias do repositório de código.

#### 6. Decisões e aprendizados

* **Testar com o modelo real.** O teste com o Ollama revelou erros de encaminhamento que não apareciam nos testes com respostas simuladas.
* **Restringir a saída do modelo.** Pedir um formato de resposta não bastou; o esquema JSON com rotas permitidas foi necessário.
* **Separar conversa e cálculo.** Valores financeiros vêm do serviço autenticado, e não da geração de texto.
* **Documentar limites.** O relatório registra o que não foi comprovado (SMTP, Open Finance live, qualidade geral das respostas), em vez de afirmá-lo.
* **Evitar somar execuções diferentes.** Resultados de datas e escopos distintos são apresentados separadamente.

# 10. DESENVOLVIMENTO

#### 1. Introdução

Este capítulo descreve como o Sigma foi construído: a organização do código, as camadas do backend e do frontend, a integração com a inteligência artificial local e o histórico de implementação.

O Sigma reúne controle financeiro pessoal, planejamento, patrimônio e assistência em uma aplicação web. A implementação documentada utiliza Java 21 e Spring Boot no backend, Angular na interface, migrações Flyway e integração local com o Ollama. Há também uma distribuição desktop com Electron.

O código-fonte da implementação está no repositório `github.com/VitorRagazzi/sigma-spring-app`. Este repositório de documentação (GitBook) reúne o relatório do projeto.

#### 4. Backend

O backend é organizado em camadas de **controladores**, **DTOs**, **serviços**, **repositórios** e **integrações**. Os módulos compartilham autenticação e persistência.

Decisões de implementação:

* **Propriedade dos dados:** as consultas usam o usuário autenticado como proprietário. Um usuário não acessa registros de outro.
* **Regras no servidor:** registros financeiros e cálculos permanecem nos serviços Java, e não no modelo de linguagem.
* **Valores monetários:** são tratados com `BigDecimal`, incluindo a distribuição de centavos em parcelamentos.
* **Banco de dados:** as alterações são versionadas por migrações Flyway e o esquema é validado pelo Hibernate.

#### 5. Frontend

A interface Angular utiliza componentes standalone, rotas carregadas sob demanda, _signals_ e serviços HTTP para consumir a API. As telas internas têm proteção de rota, navegação responsiva e suporte a temas claro e escuro.

| **Rota**                    | **Tela ou finalidade**                 |
| --------------------------- | -------------------------------------- |
| `/`                         | Página pública de apresentação         |
| `/entrar` e `/cadastro`     | Acesso e criação de conta              |
| `/inicio` e `/extratos`     | Dashboard e movimentações              |
| `/planejar` e `/patrimonio` | Planejamento e consolidação financeira |
| `/sigma`                    | Chat com o assistente financeiro       |
| `/economize` e `/alertas`   | Ofertas, fontes e insights             |
| `/perfil`                   | Preferências e gerenciamento da conta  |

As rotas constam em `frontend/src/app/app.routes.ts`.

#### 7. Integração da inteligência artificial

O assistente do projeto Python (capítulo 07) foi adaptado para o backend Java. As instruções do assistente financeiro foram incorporadas ao `OllamaAiProvider`, e o serviço passou a enviar mensagens para a API HTTP do Ollama em `localhost:11434/api/chat`. O modelo configurado por padrão é `llama3.2:1b`, e o programa Python não precisa permanecer aberto.

O fluxo é:

1. O chat Angular (porta 4200) envia a mensagem.
2. A API Spring Boot (porta 8080) recebe a requisição do usuário autenticado.
3. O serviço consulta o Ollama (porta 11434).
4. Consultas financeiras autorizadas retornam cálculos do backend; dúvidas gerais são respondidas pelo modelo.

**Histórico e contexto.** O serviço carrega até 12 mensagens recentes da conversa do usuário autenticado, em ordem cronológica. O histórico mantém contexto entre perguntas, sem compartilhar conversas entre contas. Se uma resposta falhar, o serviço não salva uma troca incompleta.

**Limites de atuação.** O assistente não registra movimentações, não transfere dinheiro e não realiza pagamentos. A classificação de consultas e as respostas livres ainda dependem do comportamento de um modelo pequeno.

#### 8. Ambiente e execução

**Requisitos (Windows):** JDK 21, Maven 3.9 ou superior, Node.js compatível com Angular 22 e pnpm 11.25.0. Para a IA, Ollama instalado, iniciado e com o modelo `llama3.2:1b` disponível. O perfil demo usa H2 e dispensa PostgreSQL.

**Primeira execução com IA** (na raiz do projeto):

```
ollama pull llama3.2:1b
.\scripts\start-local.ps1 -WithAi
```

O script compila o backend, instala as dependências do frontend e solicita uma senha demo de 12 a 72 caracteres quando `DEMO_PASSWORD` não está definida.

**Execuções posteriores:**

```
.\scripts\start-local.ps1 -WithAi -SkipBuild
```

Use `-SkipBuild` somente com o JAR e as dependências atualizados. Pressionar Enter no terminal do script encerra os dois serviços.

**Acesso:** `http://localhost:4200`. A API interativa fica em `localhost:8080/swagger-ui/index.html` (perfis demo e dev) e a saúde do backend em `localhost:8080/actuator/health`.

#### 10. Limitações do desenvolvimento

* Serviços externos de produção (SMTP e Open Finance live) não foram comprovados.
* O PostgreSQL e a infraestrutura de deploy ainda precisam ser validados.
* A publicação do código no GitHub é distinta de hospedar a aplicação na internet.
* A versão desktop usa banco próprio e não sincroniza automaticamente com a web.

Os testes que sustentam este capítulo estão no capítulo 11, e a evolução da solução está no capítulo 13.

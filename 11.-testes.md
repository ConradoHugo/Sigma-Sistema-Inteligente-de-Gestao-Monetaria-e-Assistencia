# 11. TESTES

#### 1. Introdução

A validação do Sigma combina testes automatizados do backend, verificações da interface e um teste opcional com o modelo de linguagem local. Os resultados de datas e escopos diferentes são apresentados separadamente e não devem ser somados como se fossem uma única execução.

#### 2. Estratégia de testes

| **Nível**          | **Ferramenta**                 | **O que valida**                                                                             |
| ------------------ | ------------------------------ | -------------------------------------------------------------------------------------------- |
| Backend            | Maven (`mvn test`)             | Regras, autenticação, isolamento de usuários, cálculos, idempotência e integrações simuladas |
| Frontend           | pnpm (`typecheck` e `build`)   | Verificação TypeScript e compilação do Angular                                               |
| Interface          | Cenários visuais               | Layout em 1440, 768 e 390 pixels                                                             |
| Desktop            | Testes de política do Electron | Regras de distribuição e persistência desktop                                                |
| IA com modelo real | `OllamaLiveTest` (opcional)    | Integração com o Ollama local                                                                |

O teste com o modelo real fica desabilitado na execução comum para não tornar a suíte dependente do modelo local.

#### 3. Resultado mais recente: correção do chat

Esta execução cobre a correção mais recente da integração de IA.

| **Classe**             | **Qtd.** | **Resultado** | **Cobertura principal**                                                                     |
| ---------------------- | -------- | ------------- | ------------------------------------------------------------------------------------------- |
| `OllamaAiProviderTest` | 5        | Aprovados     | Contrato HTTP, consulta autorizada, respostas inválidas, conversa geral e falhas do serviço |
| `AiHistoryTest`        | 1        | Aprovado      | Ordem do histórico, propriedade da conversa e ausência de gravação após falha               |

**Observação:** o empacotamento final usou `-DskipTests` porque os testes desse recorte já haviam sido executados. Isso não representa uma nova execução da suíte completa.

#### 4. Validações anteriores registradas

O plano de implementação registra, em 24/10/2026:

* 56 testes Java aprovados;
* 4 testes de política do Electron aprovados.

A documentação de validação também registra o build Angular, a verificação TypeScript e cenários visuais em 1440, 768 e 390 pixels.

Esses resultados são históricos e **não devem ser somados** aos 7 testes recentes como uma única execução.

Os cenários anteriores incluem:

* autenticação e isolamento de usuários;
* movimentações e cálculos;
* idempotência;
* cadastro por CPF;
* suporte;
* distribuição e persistência desktop;
* contratos simulados da Pluggy.

#### 5. Teste com o modelo real

O teste opcional `OllamaLiveTest` foi executado com o Ollama local e terminou aprovado. O cenário:

1. envia “tá aí IA?” após um histórico com resposta fixa;
2. solicita orientação para organizar as finanças;
3. verifica o encaminhamento de “Qual meu saldo?” à ferramenta financeira.

| **Exemplo**                           | **Comportamento esperado**                                                    |
| ------------------------------------- | ----------------------------------------------------------------------------- |
| “tá aí IA?”                           | Resposta conversacional do modelo, sem encaminhamento à ferramenta financeira |
| “Como organizar minhas finanças?”     | Orientação geral em português, usando as instruções do Sigma                  |
| “Qual meu saldo?”                     | Valor fornecido pelo serviço financeiro autenticado                           |
| Ollama desligado ou resposta inválida | Erro de indisponibilidade; nenhuma troca incompleta é persistida              |

Nesse teste, a geração de texto é real. O serviço financeiro é um _mock_ com valor conhecido para confirmar o encaminhamento; o teste não consulta uma conta bancária real. A aprovação confirma esse cenário de integração, e não a precisão de toda resposta que o modelo possa produzir.

#### 6. O que os testes não comprovam

* Serviços reais de SMTP e Open Finance de produção.
* Integração bancária live (apenas contratos simulados da Pluggy foram cobertos).
* A qualidade de todas as respostas livres do modelo `llama3.2:1b`.
* O comportamento da aplicação em PostgreSQL e em infraestrutura de produção.

#### 7. Erros encontrados pelos testes

O teste com o modelo real revelou erros de encaminhamento que não apareciam apenas nos testes com respostas simuladas. Os erros, e as correções feitas, estão descritos no capítulo 12 (RT04).

#### 8. Como repetir os testes

```
mvn test
pnpm --dir frontend typecheck
pnpm --dir frontend build
mvn test -Dtest=OllamaLiveTest -Dsigma.test.ollama=true
```

O último comando exige Ollama ativo e `llama3.2:1b` instalado.

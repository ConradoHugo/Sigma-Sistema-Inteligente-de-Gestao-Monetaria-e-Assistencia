# 14. REGISTRO DO USO DA IA

#### 1. Introdução

Este capítulo registra como a inteligência artificial é usada no projeto, em dois papéis distintos:

1. **IA como componente do produto:** o assistente financeiro do Sigma.
2. **IA como ferramenta de desenvolvimento:** ferramentas usadas pela equipe para produzir código, textos ou testes.

**Observação:** a tabela da seção 3 registra o uso do ChatGPT no apoio à elaboração desta documentação. Outros usos de ferramentas de IA pela equipe só devem ser acrescentados se tiverem ocorrido e puderem ser confirmados.

#### 2. IA como componente do produto

| **Item**      | **Descrição**                                                                                           |
| ------------- | ------------------------------------------------------------------------------------------------------- |
| Ferramenta    | Ollama, executado localmente                                                                            |
| Modelo padrão | `llama3.2:1b`                                                                                           |
| Comunicação   | API HTTP local do Ollama (`localhost:11434/api/chat`), chamada pelo backend Java                        |
| Componente    | `OllamaAiProvider`, com as instruções do assistente financeiro                                          |
| Contexto      | Até 12 mensagens recentes da conversa do usuário autenticado                                            |
| Modos         | Demo e Ollama, configuráveis                                                                            |
| Custos        | Sem custo por requisição, por não depender de API comercial externa (decisão registrada no capítulo 07) |

**O que a IA faz.**

* Responde a saudações e dúvidas gerais sobre organização financeira.
* Conversa em português, seguindo as instruções do Sigma.

**O que a IA não faz.**

* Não registra movimentações, não transfere dinheiro e não realiza pagamentos.
* Não produz os valores financeiros: consultas autorizadas, como o saldo, retornam cálculos feitos pelos serviços Java do usuário autenticado.
* Não garante respostas corretas em toda formulação: o modelo é pequeno, e a classificação e as respostas livres dependem do seu comportamento.

**Indicação na interface.** O cabeçalho “Conectada ao Ollama” identifica a configuração ativa. Ele não substitui a validação de uma mensagem enviada.

#### 4. Como as saídas da IA são verificadas

As práticas de verificação registradas no projeto são:

* **Cálculos no backend.** Valores monetários usam `BigDecimal` e permanecem nos serviços Java, e não na geração de texto.
* **Testes com respostas simuladas.** `OllamaAiProviderTest` cobre contrato HTTP, consulta autorizada, respostas inválidas, conversa geral e falhas do serviço.
* **Teste com o modelo real.** `OllamaLiveTest` valida saudação, orientação geral e encaminhamento da consulta de saldo. Esse teste revelou erros que os testes com respostas simuladas não mostravam.
* **Nenhuma troca incompleta é salva.** Se a resposta falhar ou for inválida, o serviço retorna erro de indisponibilidade e nada é persistido (`AiHistoryTest`).
* **Evidência honesta.** A aprovação do teste confirma o cenário testado, e não a precisão de qualquer resposta que o modelo possa produzir.

#### 5. Limites e riscos

| **Risco**                                 | **Tratamento atual**                                                                     |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| Respostas incorretas de um modelo pequeno | Cálculos fora do modelo; testes de regressão; limites documentados                       |
| Classificação fora do formato             | Esquema JSON com rotas permitidas                                                        |
| Confusão de saudações com consultas       | Saudações seguem direto para a conversa com o modelo                                     |
| Mistura de conversas entre usuários       | Histórico carregado apenas do usuário autenticado                                        |
| Dependência do hardware local             | Modelo leve (`llama3.2:1b`); desempenho varia conforme o computador                      |
| Ação financeira indevida                  | O assistente não registra movimentações, não transfere dinheiro e não realiza pagamentos |

As questões de ética, privacidade e segurança são tratadas no capítulo 15.

#### 6. Declaração de responsabilidade

A equipe Sigma deve revisar e validar o código, os textos e os testes do projeto, inclusive os materiais elaborados com apoio de ferramentas de IA, e permanece responsável pelo conteúdo final. Este registro descreve o apoio à documentação nesta etapa; ele não substitui a revisão técnica nem comprova, por si só, que todos os integrantes revisaram ou aprovaram cada item.

#### 7. Lições sobre o uso da IA no projeto

* Um modelo local pequeno atende a conversas simples, mas exige regras explícitas para tarefas estruturadas.
* Testes com respostas simuladas não substituem testes com o modelo real.
* A separação entre geração de texto e cálculo financeiro reduz o risco de valores incorretos.
* Registrar os limites da IA, e não apenas as funções, torna a documentação confiável.
